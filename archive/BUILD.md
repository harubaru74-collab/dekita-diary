# 成長可視化ページの再生成手順（現在は自動化済み）

「できたこと日記」の成長可視化ページは、**GitHub Pages**（`docs/index.html`）として公開されている静的ページ。
2026-08-25〜、この変換処理は `scripts/build_diary_page.py` として実装され、`.github/workflows/update-diary.yml`
（GitHub Actions、毎時0分に実行）が自動的に呼び出す。**Claudeが手動で変換・公開する必要はない。**

このドキュメントは、スクリプトが何をしているかの仕様書として残してある（スクリプトの修正やデバッグの際に参照する）。

**公開URL**：SETUP.md のステップ4で表示されるURL（例：`https://harubaru74-collab.github.io/dekita-diary/`）。
⚠️ GitHub Pagesは「URLを知っていれば誰でも見られる」。`docs/robots.txt` と `<meta name="robots">` で検索エンジンへの掲載は防いでいるが、完全な非公開ではない（2026-08-25、はるかちゃん了承の上でこの方式を採用）。

## 全体の流れ（`scripts/build_diary_page.py` が自動実行）

1. Google Drive の「できたこと日記」フォルダの中身を**全部**リストする（`list_diary_files()`）。
2. `diary/` にまだ無い日付のファイルがあれば、全部ダウンロードして `diary/YYYY-MM-DD.md` として保存する（内容を加筆・要約・改変しない）。
   - **2026-08-27〜**：以前は「今日・7日前・30日前・365日前」の4点だけを見に行く方式だったが、これだと「書き忘れて後から後追いで投稿した過去日の日記」が拾われない不具合があった（はるかちゃんのフィードバックで発覚）。フォルダ全体を毎回同期する方式に変更し、この問題を解消した。
3. 日付計算：今日を基準に「7日前」「30日前」「365日前」の日付を算出し、`diary/` にあれば表示、無ければ「記録なし」として扱う。
4. `archive/shell.html` を読み込み、プレースホルダーを埋めて `docs/index.html` として書き出す（新しい日記が無い日でも、日付表示を最新に保つため毎回実行する）。
5. `diary/*.md` と `docs/index.html` の変更を `git add` → `git commit` → `git push` する（差分が無ければコミットしない）。

はるかちゃん自身がやること：普段通りClaude（Cowork）と対話して日記をまとめ、その内容を**Google Driveの「できたこと日記」フォルダに保存する**（この保存だけが必要な作業。以降は全部自動）。

## カードのHTML構造（今日・1週間前・1ヶ月前・1年前 共通）

日記が**ある**場合：

```html
<div class="card today"> <!-- today / week / month / year のいずれかをclassに追加 -->
  <span class="badge">今日</span> <!-- 今日 / 1週間前 / 1ヶ月前 / 1年前 -->
  <div class="date">2026年8月25日（火）</div>
  <ul class="dekita">
    <li>（「できたこと」または「できたこと・学んだこと」の各項目。太字は<strong>のまま残す）</li>
    ...
  </ul>
  <details>
    <summary>今日のできごとを見る</summary>
    <div class="body-text">（「今日のできごと」の箇条書き項目を、1つの文章(段落)につなげたもの。
    無ければ省略。「できたこと」欄が既に箇条書きで表示されているため、
    ここは同じ内容の重複感を避けるためにあえて文章形式にしている。
    2026-08-25、はるかちゃんのフィードバックで箇条書き→文章に変更）</div>
  </details>
  <details>
    <summary>チャッピーからのコメントを見る</summary>
    <div class="chappy">（「チャッピーからのコメント」の内容。長い場合もそのまま全文を入れる）</div>
  </details>
  <p class="summary-line">（「要約」があれば入れる。無ければこの行ごと省略）</p>
</div>
```

日記が**ない**場合（1ヶ月前・1年前で、まだその時期の日記が存在しない場合など）：

```html
<div class="card empty">
  <span class="badge">1年前</span>
  <div class="emoji">🌱</div>
  <p>まだ記録がないよ<br />これからの積み重ねが楽しみだね</p>
</div>
```

「今日」の対話がまだ完了していない段階（例：過去分の見直しだけで再公開する場合など）：

```html
<div class="card empty today">
  <span class="badge">今日</span>
  <div class="emoji">📝</div>
  <p>今日の分はまだ届いていないよ<br />書いたら次回の更新で反映されるよ</p>
</div>
```

## アーカイブ（`<!-- ARCHIVE_ENTRIES -->`）の構造

`diary/*.md` を**日付の降順**（新しい日が先）で全て読み込み、1日1件として以下のブロックに変換する：

```html
<details class="entry" id="entry-2026-08-25">
  <summary>
    <span class="entry-badge">8/25</span>
    <span class="entry-headline">（その日を象徴する一言、20字程度。「できたこと」の中から代表的なものを短くまとめてよい）</span>
    <span class="entry-toggle" aria-hidden="true">▾</span>
  </summary>
  <div class="entry-body">
    <h4>今日のできごと</h4>
    <p>（カード側と同じく、箇条書きを1つの文章につなげたもの）</p>
    <h4>できたこと</h4>
    <ul>...</ul>
    <h4>要約</h4>
    <p>...</p>
    <details>
      <summary>チャッピーからのコメントを見る</summary>
      <div class="chappy">...</div>
    </details>
  </div>
</details>
```

- 最新（一番上）の1件だけ `open` 属性をつける（一番外側の`<details class="entry">`のみ。中の「チャッピーからのコメントを見る」は閉じたままでよい）。
- 見出し中の `##` の名称は日記ファイルによって多少揺れがある（「できたこと」「できたこと・学んだこと」など）ので、意味的に対応するセクションを柔軟に拾うこと。
- 「原文ママ」セクションはアーカイブ側では省略してよい（カード側の`<details>`と重複するため）。1件しかない日はカード側の内容をそのまま流用してもよい。
- **チャッピーからのコメントは「（以下略）」「〜を参照」のように省略・要約しては絶対にいけない。必ず全文をそのまま`<div class="chappy">`に入れること。** サイトを見ているだけで完結する（別のメモやファイルを見に行かなくてよい）のが必須要件。長いので`<details>`で畳んでおき、クリックで展開する形にする（CSSは`.entry-body details`に対応済み）。

## カレンダー機能（2026-08-27追加）

「今日・1週間前・1ヶ月前・1年前」の4枚は、実は**クライアント側(JavaScript)で
好きな日付を起点に組み替えられる**。ヘッダー下の日付ピッカー（`#date-picker`）
で日付を選ぶと、その日を起点に7日前/30日前/365日前を計算し直して4枚を
再表示する。「今日に戻す」ボタン（`#date-reset`）で元に戻る。

- Python側は `render_card_body()` で全日記分の「カード本体HTML」（日付・でき
  たこと・詳細部分。外側の`<div class="card ...">`とbadgeは含まない）を作り、
  `{{DIARY_CALENDAR_JSON}}` として`<script type="application/json" id="diary-
  calendar-data">`に丸ごと埋め込む。
- JS側はこのJSONと日付計算だけを行い、表示ロジック自体はPython側の
  `render_card_body()`の出力をそのまま使う（二重管理を避けるため）。
- 「毅さんからのメッセージ」カード（後述）は、選んだ日が実際の今日でない
  限り非表示にする（`#message-card-slot`のdisplay切り替え）。
- ページの読み込み・再構築のたびに全日記分のHTMLをJSONとして埋め込むため、
  日記の日数が増えるとページのファイルサイズも増える。数百日分程度までは
  問題ない想定だが、極端に増えた場合は埋め込み方式の見直し（ページネーション等）
  を検討すること。

## メンタルコンディショニング機能（2026-08-25追加、任意セクション）

しんどい・悩みがある日だけ、**Cowork側が日記をまとめる対話の中で判断して**、日記本文に以下の3セクションを追加で書いてもらう。元気な日はこの3セクションを書かなくてよい（何も表示されないのが正しい動作）。

```markdown
## メンタル状態
今日のエネルギー: しんどい（元気／普通／しんどい、のいずれか）
ひとこと: （今日の状態を一言で）

## 乗り越えログ
2026-08-24: 弁護士さん・社労士さんに相談して気持ちを整理できた日。
（Google Driveの「おぼえがき」フォルダや過去の diary/*.md から、
　今と似た悩みを行動で乗り越えた具体的な日付・エピソードを1つ選ぶ）

## 毅さんからのメッセージ
（毅さん口調の、温かく芯のある励ましメッセージを2〜4文程度。
　AIが毅さんの人柄を推測して生成したものであり、本人の実際の発言ではない
　ことを前提とする）
```

- この3セクションは `scripts/build_diary_page.py` の `HEADER_MAP` に `mental` / `overcome_log` / `takeshi_message` として登録済み。
- 「毅さんからのメッセージ」が書かれている日だけ、ページ上部に `🫂 今日のひとこと` という専用カード（`render_message_card()`、`<!-- MESSAGE_CARD -->`）が表示される。書かれていなければカード自体が出ない。
- アーカイブ側にも「この日のひとことを見る」として同じ内容が残る（過去の記録として振り返れるように）。
- 「エネルギー: ○○」の行は `message-energy` として抽出表示される（正規表現 `エネルギー[:：]\s*(.+)` でパース）。

## 置換するプレースホルダー一覧

| プレースホルダー | 内容 |
|---|---|
| `{{TODAY_DATE_JP}}` | 今日の日付（例：`2026年8月25日（火）`） |
| `{{DIARY_COUNT}}` | `diary/*.md` の総ファイル数 |
| `{{FIRST_DATE_JP}}` | 一番古い日記の日付（例：`2026年8月16日`） |

## 注意事項

- HTML特殊文字（`&` `<` `>`）はエスケープすること（スクリプトの`esc()`が対応済み）。
- 日記の内容は要約・改変せず、Google Driveの内容をそのまま反映する（「できたこと」欄の太字強調は保持してよい）。
- 既存の `diary/*.md` の内容は変更しない（過去日の内容を書き換えない）。
- Google Drive の text/plain ファイルは、Markdown記号がバックスラッシュでエスケープ（`\#` `\*\*` `\-`）されていたり、絵文字が `ð` のような文字化けになっていることがある（`scripts/build_diary_page.py` の `unescape_md()` / `clean_mojibake()` で対応済み）。
- 日記作成側（Cowork対話）が、まれに `[stated]` のようなデバッグ用タグを箇条書きの行頭に紛れ込ませて保存することがある（2026-08-25、`diary/2026-08-25.md` で発生。「文が途中で切れている」ように見えてしまう不具合）。`scripts/build_diary_page.py` の `list_items()` で `^\[[a-zA-Z_-]+\]\s*` にマッチする先頭タグを防御的に除去しているが、根本原因は日記作成側にあるため、繰り返し発生する場合はそちら側の見直しも検討すること。
- スクリプトの修正が必要な場合は、まず `python scripts/build_diary_page.py` をローカルで動かして(要`GDRIVE_SA_KEY_JSON`環境変数)、`docs/index.html` の出力を確認してから push する。
