# 成長可視化ページの再生成手順

「できたこと日記」の成長可視化ページは、Claude Artifact として**非公開（private）**で公開されている静的ページ。
はるかちゃんがClaudeとの対話で今日の日記をまとめ終えたタイミングで、その同じ会話の中でこのページを再生成・再公開する（[`../ROUTINE.md`](../ROUTINE.md)参照。Google Driveや自動Routineは使わない、対話の流れの中での即時更新）。

**公開URL（固定・変えないこと）**：
https://claude.ai/code/artifact/1a759afc-2415-432b-9d53-161c7c476f08

（非公開のまま。誰かと共有したくなった場合のみ、はるかちゃん自身がページの共有メニューから設定する）

## 全体の流れ

1. Claudeとの対話で、今日の日記が「原文ママ／今日のできごと／できたこと／要約／チャッピーからのコメント」の形にまとまり、はるかちゃんがOKを出す。
2. その内容を `diary/YYYY-MM-DD.md` として保存する（内容を加筆・要約・改変しない。対話でまとまった文章をそのまま使う）。
3. 日付計算：今日を基準に「7日前」「30日前」「365日前」の日付を算出する。
4. `diary/` の中に、算出した3つの日付のファイルがあるか確認する（無ければ「記録なし」として扱う。Google Driveへの問い合わせは不要）。
5. `archive/shell.html` を読み込み、以下のプレースホルダーを埋めて完成したHTMLを作る（保存先リポジトリには書き戻さず、公開直前の一時ファイルとして生成すればよい）。
6. 完成したHTMLをArtifactツールで、`url` にBUILD.md冒頭のURLを指定して再公開する（`favicon: 🌱`、`title: "できたこと日記 — 成長のあしあと"`）。**Artifactは非公開のまま**（誰かに共有する場合はユーザー自身の判断で行う。ここで共有・公開範囲を変更しない）。
7. `diary/*.md` の追加・更新を `git add` → `git commit` → `git push` する（バックアップの永続化が目的。プッシュ先はこのリポジトリの既定ブランチ）。
8. 同じ会話の中で「ページを更新したよ」と伝える（自動通知の仕組みは使わない）。

## カードのHTML構造（今日・1週間前・1ヶ月前・1年前 共通）

日記が**ある**場合：

```html
<div class="card today"> <!-- today / week / month / year のいずれかをclassに追加 -->
  <span class="badge">今日</span> <!-- 今日 / 1週間前 / 1ヶ月前 / 1年前 -->
  <div class="date">2026年8月25日（火）</div>
  <ul class="dekita">
    <li>（「できたこと」または「できたこと・学んだこと」の各項目。太字は<strong>のまま残す）</li>
    ...
  </ul>
  <details>
    <summary>今日のできごと・原文を見る</summary>
    <div class="body-text">（「今日のできごと」の内容。無ければ省略）</div>
  </details>
  <details>
    <summary>チャッピーからのコメントを見る</summary>
    <div class="chappy">（「チャッピーからのコメント」の内容。長い場合もそのまま全文を入れる）</div>
  </details>
  <p class="summary-line">（「要約」があれば入れる。無ければこの行ごと省略）</p>
</div>
```

日記が**ない**場合（1ヶ月前・1年前で、まだその時期の日記が存在しない場合など）：

```html
<div class="card empty">
  <span class="badge">1年前</span>
  <div class="emoji">🌱</div>
  <p>まだ記録がないよ<br />これからの積み重ねが楽しみだね</p>
</div>
```

「今日」の対話がまだ完了していない段階（例：過去分の見直しだけで再公開する場合など）：

```html
<div class="card empty today">
  <span class="badge">今日</span>
  <div class="emoji">📝</div>
  <p>今日の分はまだ届いていないよ<br />書いたら次回の更新で反映されるよ</p>
</div>
```

## アーカイブ（`<!-- ARCHIVE_ENTRIES -->`）の構造

`diary/*.md` を**日付の降順**（新しい日が先）で全て読み込み、1日1件として以下のブロックに変換する：

```html
<details class="entry" id="entry-2026-08-25">
  <summary>
    <span class="entry-badge">8/25</span>
    <span class="entry-headline">（その日を象徴する一言、20字程度。「できたこと」の中から代表的なものを短くまとめてよい）</span>
    <span class="entry-toggle" aria-hidden="true">▾</span>
  </summary>
  <div class="entry-body">
    <h4>今日のできごと</h4>
    <ul>...</ul>
    <h4>できたこと</h4>
    <ul>...</ul>
    <h4>要約</h4>
    <p>...</p>
    <details>
      <summary>チャッピーからのコメントを見る</summary>
      <div class="chappy">...</div>
    </details>
  </div>
</details>
```

- 最新（一番上）の1件だけ `open` 属性をつける（一番外側の`<details class="entry">`のみ。中の「チャッピーからのコメントを見る」は閉じたままでよい）。
- 見出し中の `##` の名称は日記ファイルによって多少揺れがある（「できたこと」「できたこと・学んだこと」など）ので、意味的に対応するセクションを柔軟に拾うこと。
- 「原文ママ」セクションはアーカイブ側では省略してよい（カード側の`<details>`と重複するため）。1件しかない日はカード側の内容をそのまま流用してもよい。
- **チャッピーからのコメントは「（以下略）」「〜を参照」のように省略・要約しては絶対にいけない。必ず全文をそのまま`<div class="chappy">`に入れること。** サイトを見ているだけで完結する（別のメモやファイルを見に行かなくてよい）のが必須要件。長いので`<details>`で畳んでおき、クリックで展開する形にする（CSSは`.entry-body details`に対応済み）。

## 置換するプレースホルダー一覧

| プレースホルダー | 内容 |
|---|---|
| `{{TODAY_DATE_JP}}` | 今日の日付（例：`2026年8月25日（火）`） |
| `{{DIARY_COUNT}}` | `diary/*.md` の総ファイル数 |
| `{{FIRST_DATE_JP}}` | 一番古い日記の日付（例：`2026年8月16日`） |

## 注意事項

- HTML特殊文字（`&` `<` `>`）はエスケープすること。
- 日記の内容は要約・改変せず、対話でまとまった文章をそのまま反映する（「できたこと」欄の太字強調は保持してよい）。
- 既存の `diary/*.md` の内容は変更しない（過去日の内容を書き換えない）。
- 2026-08-16〜08-24分はGoogle Driveからの初期移行データ。当時の text/plain ファイルはMarkdown記号がバックスラッシュでエスケープ（`\#` `\*\*` `\-`）されていたり、絵文字が `ð` のような文字化けになっていたことがあったが、`diary/*.md` には既に正常化済みなので今後意識しなくてよい。
- Artifactの再公開が失敗した場合も、GitHubへのバックアップ push 自体は独立して完了させること（どちらかが失敗しても、もう片方の失敗理由になってはいけない）。
